# Доступность текста

Документация SONDER должна быть понятной читателям с разным уровнем подготовки. При подготовке материалов необходимо учитывать следующие правила.

## Правила и примеры

### Заголовки

Используйте понятные заголовки, которые отражают содержание раздела.

| Плохо | Хорошо |
| --- | --- |
| Подробности | Как пациент подтверждает согласие |
| Раздел 4 | Ограничения текущей версии |

### Цвет

Не передавайте смысл только с помощью цвета, например обозначая важную информацию исключительно красным или зелёным цветом. Добавляйте слово, значок с подписью или текстовый статус.

| Плохо | Хорошо |
| --- | --- |
| Анкеты со статусом, выделенным красным, не заполнены. | Статус «Не заполнена» выделен красным цветом и подписан словами. |
| В таблице зелёным отмечены готовые функции. | В таблице столбец «Статус» содержит значения «Работает» и «В разработке». |

### Ссылки

Для ссылок используйте информативные подписи, из которых понятно, куда они ведут.

| Плохо | Хорошо |
| --- | --- |
| Список слов описан [тут](terminology.md). | Список слов описан в разделе [«Терминология и ограничения»](terminology.md). |

### Длина предложения

Предложение содержит не более 25 слов. Если длиннее, разбейте его на два.

| Плохо | Хорошо |
| --- | --- |
| Пациент получает ссылку по СМС, заполняет анкету на телефоне, подтверждает согласие кодом из СМС, после чего врач видит ответы в карточке и может подготовиться к приёму заранее. (27 слов) | Пациент получает ссылку по СМС и заполняет анкету на телефоне. Затем он подтверждает согласие кодом из СМС. После этого врач видит ответы в карточке и готовится к приёму. |

### Таблицы

Для таблиц используйте понятные заголовки столбцов и сохраняйте логичную структуру данных.

| Плохо | Хорошо |
| --- | --- |
| Таблица без заголовков, в одной ячейке числа и описания. | Столбцы «Раздел анкеты», «Количество вопросов», «Обязательный». В каждом столбце один тип данных. |

### Изображения

Для изображений, содержащих важную информацию, добавляйте текстовое описание. Декоративные изображения не должны заменять текстовые инструкции.

| Плохо | Хорошо |
| --- | --- |
| `![Скриншот](screen.png)` и в тексте: «Нажмите на кнопку, как показано на рисунке». | `![Экран анкеты с кнопкой «Отправить» внизу](form-submit.png)` и в тексте: «Нажмите кнопку «Отправить» в конце анкеты». |
| Инструкция только на картинке. | Инструкция написана текстом, а картинка поясняет. |

### Предупреждения и ограничения

Предупреждения и ограничения продукта формулируйте однозначно, чтобы читатель мог понять их без дополнительного контекста.

| Плохо | Хорошо |
| --- | --- |
| Возможны некоторые ограничения. | Ограничение: система не интерпретирует ответы пациента. |
| Функция пока недоступна. | Функция «Напоминание пациенту» планируется; сейчас она недоступна. |

## Дополнительные правила

### Простые слова

Выбирайте общеупотребительное слово вместо редкого, если смысл тот же.

| Плохо | Хорошо |
| --- | --- |
| Осуществить интеграцию | Подключить |
| Индивидуализированный подход | Подход к каждому пациенту |
| Валидация формы | Проверка формы |

### Расшифровка аббревиатур

Расшифровывайте аббревиатуру при первом употреблении. Правила – в разделе [«Орфография, числа и даты»](spelling.md).

### Списки вместо длинных перечислений

Если в предложении больше трёх однородных элементов, оформите список.

| Плохо | Хорошо |
| --- | --- |
| В анкете есть общие сведения, аллергии, принимаемые препараты, хронические заболевания и перенесённые процедуры. | В анкете есть:<br>- общие сведения<br>- аллергии<br>- принимаемые препараты<br>- хронические заболевания<br>- перенесённые процедуры |

### Структура для сканирования

Читатель сначала просматривает страницу. Помогите ему:

- ставьте главную мысль в начало раздела;
- делите текст заголовками на смысловые части;
- выделяйте жирным только ключевое.

### Интерфейс и мобильные устройства

Анкеты открывают на телефоне. Для текстов интерфейса:

- один вопрос на экран или один блок вопросов на небольшой экран;
- кнопки с глаголом: «Отправить», «Подтвердить»;
- ошибка объясняет, что делать (подробно в разделе [«Тексты интерфейса и анкет»](interface.md)).

## Проверка перед публикацией

Перед публикацией необходимо проверить, понятны ли заголовки и ссылки, можно ли понять основную информацию без визуальных подсказок и не затрудняют ли оформление и формулировки восприятие текста.

Быстрый тест:

1. Прочитайте только заголовки. Понятно ли, о чём документ?
2. Прочитайте только подписи ссылок. Понятно ли, куда они ведут?
3. Представьте, что цвета нет. Теряется ли смысл?
4. Закройте изображения. Понятна ли инструкция?
5. Найдите самое длинное предложение. Больше ли в нём 25 слов?
