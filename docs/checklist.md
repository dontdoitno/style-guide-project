# Чек-лист перед публикацией

Пройдите чек-лист сверху вниз. Если пункт не выполнен, исправьте текст и вернитесь к началу блока. К каждому пункту добавлен пример того, что проверять.

## Смысл документа

- [ ] Название и структура документа понятны.

    Пример: название «Правила заполнения анкеты пациентом», а не «Заметка 3».

- [ ] Фактические возможности не смешаны с планами и гипотезами.

    Пример: «Напоминание планируется» – в разделе «Ограничения», а не в описании работающих функций.

- [ ] Документ не противоречит главной странице и связанным материалам.

    Пример: стадия продукта везде указана как Pre-MVP; название лид-магнита одинаковое.

- [ ] Текст адресован одному читателю.

    Пример: в начале указано «Для косметологов».

## Формулировки

- [ ] Термины согласованы со «Словарём формулировок».

    Пример: «анкета» везде, без «формы» и «опросника».

- [ ] В тексте нет слов из красного списка.

    Пример: нет «преддиагностики», «оценки риска», «красных флагов», «ИИ».

- [ ] Нет гарантий безопасности, медицинского результата или полной юридической защиты.

    Пример: вместо «защитит от претензий» – «хранит согласия вместе с анкетой».

- [ ] Нет превосходных степеней и пустых слов.

    Пример: вместо «лучшее решение» – конкретное свойство.

## Числа и источники

- [ ] Числа сопровождаются источником и датой версии, если это необходимо.

    Пример: «ДД.ММ.ГГГГ, расчётная таблица проекта».

- [ ] Числа совпадают с актуальной версией расчётной таблицы.

    Пример: тариф и расчёты на его основе сверены на текущую дату.

- [ ] Формат чисел, денег и дат единый.

    Пример: «2 500 ₽/мес.», «18.08.2026», «5%».

## Оформление

- [ ] Markdown-разметка, таблицы и внутренние ссылки проверены.

    Пример: ссылка `[[Анкета пациента]]` ведёт на существующий документ.

- [ ] Заголовки идут по порядку: `#`, `##`, `###`.

    Пример: после `##` не сразу `####`.

- [ ] У блоков кода указан язык, у изображений есть описание.

## Доступность

- [ ] Заголовки и подписи ссылок понятны без контекста.

    Пример: «раздел «Структура документа»», а не «здесь».

- [ ] Смысл не передаётся только цветом.

- [ ] Предложения не длиннее 25 слов.

- [ ] Аббревиатуры расшифрованы при первом употреблении.

## Тексты для пациента

Проверяйте, если документ или текст читает пациент.

- [ ] Нет терминов и аббревиатур.
- [ ] Ошибки объясняют, что делать.
- [ ] Согласие сопровождено пояснением простыми словами.

## Быстрая проверка за две минуты

Если времени мало, проверьте пять вещей:

1. Нет слов из красного списка.
2. Нет обещаний результата.
3. Планы отделены от работающих функций.
4. У каждого числа есть источник и дата.
5. Ссылки открываются.

## Автоматический поиск по красному списку

Чтобы найти опасные слова в папке с вашими материалами, выполните команду в терминале. Замените `путь/к/папке` на свою папку.

```bash
grep -rniE "преддиагност|выявляет противопоказ|оценк[аи] риск|красные флаги|поддержк[аи] принятия решений|помощь в диагностике|движок правил|база правил|искусственн|нейросет|(^|[^[:alpha:]])(AI|ИИ)([^[:alpha:]]|$)" путь/к/папке
```

Не запускайте команду на самом руководстве: слова красного списка встречаются там как примеры «плохо». Команда находит подозрительные места, но не заменяет чтение текста.

## После публикации

- Проверьте, как страница выглядит на телефоне.
- Откройте все ссылки в опубликованном виде.
- Если вы изменили правило в руководстве, добавьте запись в [историю изменений](changelog.md).
