# Markdown и внутренние ссылки

Единая разметка нужна, чтобы документы одинаково отображались в базе знаний и на сайте. Ниже – правила и готовые примеры, которые можно копировать.

## Внутренние ссылки

Используйте внутренние ссылки в согласованном формате базы знаний: `[[Название документа]]` или `[[Папка/Документ|Понятная подпись]]`.

| Что нужно | Как писать | Результат |
| --- | --- | --- |
| Ссылка на документ | `[[Анкета пациента]]` | Анкета пациента |
| Ссылка на раздел | `[[Анкета пациента#Ограничения]]` | Анкета пациента, раздел «Ограничения» |

Ссылка с другой подписью и ссылка на документ в папке:

```markdown
[[Анкета пациента|Как устроена анкета]]
[[Продукт/Анкета пациента|Анкета пациента]]
```

Если такая ссылка стоит внутри ячейки таблицы, вертикальную черту экранируйте обратной косой чертой: `\|`.

На сайте руководства страницы связаны обычными относительными ссылками Markdown: `[Терминология](terminology.md)`.

## Проверка ссылок

Перед публикацией проверяйте, что цель ссылки существует, а относительный путь корректен.

- Откройте ссылку и убедитесь, что она ведёт на нужный документ.
- Если вы переименовали документ, найдите все ссылки на старое название.
- Для сайта запустите сборку `mkdocs build --strict`: она остановится, если ссылка ведёт на несуществующую страницу.

| Плохо | Хорошо |
| --- | --- |
| `[[Анкета пациента v2 финал]]` (такого документа нет) | `[[Анкета пациента]]` |
| `[Шаблон](../template.md)` (неверный относительный путь) | `[Шаблон](template.md)` |

## Подписи ссылок

Подпись ссылки должна объяснять, куда она ведёт; не используйте неинформативные подписи вроде «здесь».

| Плохо | Хорошо |
| --- | --- |
| Правила описаны [здесь](terminology.md). | Правила описаны в разделе [«Терминология и ограничения»](terminology.md). |
| [Ссылка](template.md) | [Шаблон документа](template.md) |
| Подробнее: [https://example.com/long/path](https://example.com/long/path) | Подробнее: [Описание формата дат](https://example.com/long/path) |

## Внешние ссылки

- Подпись объясняет, что откроется: «Расчётная таблица проекта (Google Sheets)».
- Не вставляйте длинный адрес как текст.
- Если ссылка ведёт на файл, укажите формат и размер, когда он большой: «Презентация (PDF, 4 МБ)».

## Выделение

Выделяйте жирным ключевые сообщения, но не превращайте в выделение целые абзацы.

| Приём | Когда использовать | Пример |
| --- | --- | --- |
| **Жирный** | Ключевое слово или важное ограничение | Продукт **не является медицинским изделием**. |
| *Курсив* | Название, термин при первом упоминании | Стадия *Pre-MVP* |
| `Код` | Имена файлов, команды, технические значения | Откройте файл `mkdocs.yml` |
| «Кавычки» | Названия разделов и документов | Раздел «Структура документа» |

Плохо: **Анкета собирает ответы, которые пациент заполняет до визита, и показывает их врачу.** (весь абзац выделен).

Хорошо: Анкета собирает ответы, которые пациент заполняет **до визита**, и показывает их врачу.

Не используйте подчёркивание для выделения: его легко спутать со ссылкой.

## Списки

- Для маркированных списков используйте дефис `-`, а не `*` и `+`.
- Для нумерованных – `1.`, `2.`, `3.`.
- Перед списком и после него оставляйте пустую строку.
- Вложенность – два пробела на уровень, не больше двух уровней.

```markdown
Анкета содержит разделы:

- общие сведения;
- аллергии:
  - на лекарства;
  - на косметические средства;
- принимаемые препараты.
```

## Таблицы

Таблицы должны иметь понятные заголовки столбцов и содержать сопоставимые данные.

- Разделитель заголовка пишите как `| --- | --- |`, без двоеточий.
- Количество столбцов в каждой строке одинаковое.
- Вертикальную черту внутри ячейки экранируйте: `\|`.
- Для переноса строки в ячейке используйте `<br>`.

```markdown
| Плохо | Хорошо |
| --- | --- |
| Нажмите здесь. | Скачайте шаблон. |
```

## Блоки кода

Для команд и фрагментов кода используйте тройные обратные кавычки с указанием языка.

```bash
mkdocs serve
```

Для коротких значений внутри предложения используйте одинарные обратные кавычки: `docs/index.md`.

## Цитаты и примечания

Для цитаты или выделенного примера используйте `>`.

```markdown
> **Пример.**
> Плохо: «Нажмите здесь».
> Хорошо: «Скачайте шаблон договора».
```

## Изображения

- У каждого изображения есть описание в квадратных скобках.
- Описание сообщает, что изображено и зачем оно нужно.
- Файлы называйте латиницей без пробелов: `intake-form-step-1.png`.

| Плохо | Хорошо |
| --- | --- |
| `![](img1.png)` | `![Экран анкеты: вопрос об аллергиях с вариантами «Да», «Нет», «Не знаю»](intake-form-step-1.png)` |
| `![скриншот](img1.png)` | `![Карточка пациента: ответы сгруппированы по разделам анкеты](patient-card.png)` |

## Заголовки

- Перед заголовком и после него оставляйте пустую строку.
- В конце заголовка не ставьте точку и двоеточие.
- Не повторяйте одинаковые заголовки в одном документе.
- Документ начинается с `#`.

## Проверка перед публикацией

В репозитории руководства автоматически работают две проверки: линтер Markdown (`markdownlint`) и сборка сайта в строгом режиме. Если проверка не прошла, прочитайте сообщение: оно указывает файл и строку.

| Сообщение | Что значит | Как исправить |
| --- | --- | --- |
| MD022 | Вокруг заголовка нет пустых строк | Добавьте пустую строку до и после |
| MD032 | Список не отделён от текста | Добавьте пустую строку до и после списка |
| MD040 | У блока кода нет языка | Допишите язык после открывающих кавычек |
| WARNING: a relative link | Ссылка ведёт на несуществующую страницу | Исправьте путь или создайте страницу |
