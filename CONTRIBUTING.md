# Как внести вклад в руководство по стилю

## Как предложить изменение
1. Создайте ветку от `main`: `git checkout -b docs/<краткое-описание>`.
2. Внесите правки в файлы в папке `docs/`.
3. Запустите локальную сборку и линтер (см. ниже).
4. Отправьте ветку и создайте Pull Request в `main`.

## Требования к коммитам (Conventional Commits)
Формат: `<тип>: <краткое описание>`

Типы:
- `docs` — изменения в тексте руководства;
- `feat` — новый раздел или функциональность сайта;
- `fix` — исправление ошибок и опечаток;
- `style` — форматирование без изменения смысла;
- `ci` — изменения в CI/CD;
- `chore` — прочие служебные изменения.

Примеры: `docs: add accessibility section`, `fix: correct broken link in terminology`.

## Процесс ревью
1. Автор создаёт PR и описывает изменения.
2. Проверки CI (линтинг и сборка) должны пройти успешно.
3. Минимум один участник проверяет PR и оставляет комментарии.
4. Автор вносит правки новыми коммитами в ту же ветку.
5. После одобрения PR вливается в `main`, сайт публикуется автоматически.

## Локальная сборка
```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
mkdocs serve
```
Сайт будет доступен по адресу http://127.0.0.1:8000.
Линтинг: `npx markdownlint-cli2 "docs/**/*.md"`.

## Как добавить новый раздел
1. Создайте файл `docs/<название>.md` с заголовком первого уровня.
2. Добавьте его в `nav` в файле `mkdocs.yml`.
3. Проверьте сборку (`mkdocs build --strict`) и линтер.
4. Оформите PR по процессу выше.
